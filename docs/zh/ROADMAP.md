## 已实现

静态二维/三维/四维索引、几何与轨迹扩展、分层包结构、统一近邻与 DBSCAN 遍历、二维缓冲复用、安全二维/三维恢复，以及数值与存储回归已在源码实现。浏览器演示已调用 MoonBit 编译核心，展示真实内部包围盒，在相同种子数据上比较真实 Flatbush/RBush，并提供完整结果校验和原始计时导出。详见[接口](API_SPECIFICATION.md)和[验证](VALIDATION.md)。

## 后续工作

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| 随后 | 多维基准 | 明确分布、编译器、目标、构建/查询开销及最坏重叠场景 |
| 随后 | 直接打包构建 | 测量峰值内存后决定是否替换临时层级 |
| 以后 | 更多安全持久化格式 | 有版本的二进制格式与校验，不把原始数组命名为协议 |

动态插删、坐标投影、分布式索引与 GPU 执行不属于当前静态索引约定。文档不把预期吞吐或延迟写成已达成结论，后续优化由实测瓶颈驱动。

## 公开证据与后续真实案例

当前已有高效竞品适配、固定版本 OurAirports 加载、456 场景诊断、可扩展矩阵及真实三维/四维功能展示。标准轮跑分和实际内存尚待完成；后续加入黑白 Benchmark 图表、保留落后和失败结果，并通过 GitHub Pages 发布稳定网站。二维直接构建已实现，三维/四维同类优化仍待按瓶颈推进。

真实应用案例只列为规划：公开建筑轮廓的地图视口选择、机场/跑道范围查询、GeoLife 空间与时间窗口探索。各案例需标注来源与单位、区分包围盒候选和精确几何、完整校验结果并提供可复现流程。NYC 与 GeoLife 接入前还需核对各自数据条款。
